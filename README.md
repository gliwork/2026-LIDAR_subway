# laser-radar — обнаружение препятствий спереди: 3 лазерных веера + 1 USB-камера

Здесь представлен работоспособный скрипт, который демонстрирует определение дистанции до препятствия с помощью обычной камеры и линейных или точечных лазеров
Скрипт выводит изображение с камеры с комментариями/расстоянием до препятствия, а также тепловая карта, показывающая расстояние до препятствий, а также угол (0-вертикально вверх), на котором находятся точки препятствия

В папке /calibration находятся изображения лазерных пучков на препятствии на разных расстояниях и excel-файл с соответствующими расстояниями (для конкретной конфигурации аппаратной части, продемонстрированной в презентации)




> English version: [README.md](README.md)

`laser_radar_final.py` измеряет дистанцию до ближайшего препятствия перед
транспортом по отражениям **трёх лазерных вееров**, которые видит USB-камера,
— в живом режиме, в окне; по умолчанию ничего на диск не записывается.

| что отчитывается | как находится |
|---|---|
| **стена** (ближайшая поверхность) | строка дистанций, зажигающая длинные угловые «полосы» сразу в ≥ 2 веерах (оценка взвешена по длине полосы, сглаживается EMA) |
| **ближайший объект** (MIN) | яркое *пятно* на лазерном следе, вытянутое ≥ 5 px **вдоль** линии; дистанция берётся только от пикселей ближней грани пятна; одного веера достаточно на любой дистанции; должно держаться 3 кадра подряд (0.3 м / 4°) |
| **подозрительные направления** | столбцы углов, в которых не светится *ни одной* ячейки — луч ушёл на бесконечность или поверхность не отразила его обратно; дистанции там доверять нельзя (фиолетовые дуги) |
| **полярная карта-«тепловая»** | вся матрица (угол × дистанция) с накоплением за 3 кадра: 1/3 тускло … 3/3 ярко |

## Как это работает

Камера видит следы трёх неподвижных лазерных плоскостей, спроецированных на
первую поверхность перед ней:

* **L** / **R** — два боковых веера, почти вертикальные линии изображения
  (L направлен влево, R — вправо);
* **B** — нижний веер, горизонтальная линия изображения.

Каждый веер — фиксированная 3D-плоскость; след, который он оставляет на
поверхности на дистанции *d*, — это прямая линия изображения, положение
которой зависит только от *d*. Калибровка по 28 изображениям (см. ниже)
измеряет это положение на каждой известной дистанции, поэтому след *любой*
поверхности сразу даёт дистанцию — чистый параллакс, без time-of-flight.

Вместо подгонки линий по каждому кадру кадр **пересэмплируется в радар-матрицу**:

```
столбцы = угол поворота θ, по 0.3°, 0 … 359.7° (1200 столбцов),
         отсчитывается от горизонтальной вокруг точки исчезания C
         (точки, где все лазерные следы схлопываются при d → ∞;
         C ≈ (614, 225) в этом случае)
строки  = дистанция от камеры: 2.0 → 13.2 м с шагом 2 см,
         13.2 → 40 м с шагом 1 м   (588 строк)

ячейка (θ, d) = 0..3  =  сколько из трёх вееров имеют свой
         калиброванный след на дистанции d, пересекающий пиксель,
         выбранный на луче из C под углом θ
```

Всё сэмплирование — 3 вызова `cv2.remap` по заранее вычисленным картам,
именно это и держит цикл быстрым (несколько мс на кадр на CPU ноутбука).

Ниже ближайшей калибровочной дистанции (1.955 м) и за дальнейшей (13.2 м)
линия следа экстраполируется по локальной **ветви 1/d** (проективное
поведение: наклон ~ k/d², смешивание с картой на интервале 0.15 м), поэтому
геометрия валидна от 0.25 м до 45 м, хотя измеренная карта покрывает
1.955–13.2 м. Сами «радарные» строки начинаются с 2 м (ближе не
сэмплируется); `--sub-cal` разрешает кандидатов ближе калибровочного
пола (экспериментально).

### Слои защиты от «призраков» (отчёт по пятну — только если сходятся все)

1. **top-hat маска** — пиксель проходит, только если он ярче локального
   фона (31 px); плоские яркие области (окна, светлая стена) исчезают;
2. **статическая junk-маска** (`radar_junk.npy`, прилагается) — ячейки,
   светящиеся в ≥ 15 из 28 калибровочных кадров, это статичные структуры
   комнаты (уголки, блики на полу) — они вычитаются из матрицы;
3. **живая junk-маска** — за первые 120 живых кадров все ячейки, светящиеся
   в ≥ 25 % из них, считаются статичной обстановкой *текущей* сцены и
   маскируются (полоса стены ± 0.8 м исключена: стена — это само
   измерение);
4. **проверка засветки** — настоящий лазерный след — самая яркая вещь в
   кадре; хотя бы половина ближайших пикселей пятна должна лежать на
   уровне p99 − 25 гистограммы яркости кадра;
5. **правило протяжённости** — пятно должно растягиваться ≥ 5 px *вдоль*
   своей лазерной линии (пересечение линий даёт вспышку в 1–2 px, объект
   зажигает протяжённый участок следа);
6. **отступ от стены** — ближний объект должен находиться ≥ 0.25 м впереди
   стены;
7. **3-кадровая персистенция** — кандидат должен повториться (в пределах
   0.3 м / 4°) в 3 кадрах подряд, прежде чем быть отчитанным.

## Файлы

| файл | роль |
|---|---|
| `laser_radar_final.py` | живое приложение (точка входа): радар-матрица, детекция стены / ближайшего объекта / подозрительных направлений, полярный вид |
| `laser_sensor.py` | базовая библиотека: 3D-модель камеры и плоскостей вееров, извлечение лазерных линий, `LineMap` — карты «линия↔дистанция», калибровочный I/O (`load_calibration`) |
| `calibration.json` | калибровка: `model` (камера + 3 плоскости вееров), `maps` (по 28 карт линий на веер, 1.955–13.2 м), `report` (остатки подгонки по кадрам), `meta` |
| `calibration/` | 28 калибровочных изображений (`WIN_*.jpg`) + `camera_calibration.xlsx` с эталонными дистанциями — нужны только для `--test` и пересборки junk-маски |
| `radar_junk.npy` | готовая статическая junk-маска (пересборится сама, если файла нет) |
| `requirements.txt` | зависимости Python |

Для живого приложения нужны только **numpy** и **opencv-python** (GUI-сборка,
*не* `-headless`); `openpyxl` дополнительно нужен только для `--test` /
пересборки junk-маски (он читает калибровочный xlsx).

## Установка

```bash
python3 -m venv venv
. venv/bin/activate            # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Работает на Linux (V4L2, `/dev/videoN`) и Windows (DSHOW); индексация USB-
камер может различаться между системами.

## Быстрый старт

```bash
python3 laser_radar_final.py                # живая камера 0 (только окно, на диск ничего)
python3 laser_radar_final.py --cam 1        # другая камера
python3 laser_radar_final.py --video f.mp4  # проиграть видео
python3 laser_radar_final.py --test         # валидация по 28 изображениям
python3 laser_radar_final.py --build-calib  # сохранить точку исчезания в radar_calibration.json
```

Клавиши: **q** / **ESC** — выход.

Окно показывает аннотированный кадр (слева) и полярную карту (справа,
строки = дистанция, столбцы = угол):

* **красный круг + `MIN x.xx m / θ xx° / sheet X`** — подтверждённый
  ближний объект (3 кадра подряд); серый круг = кандидат ещё
  накапливается;
* `wall x.xx m` — сглаженная (EMA) дистанция до ближайшей поверхности;
* **фиолетовые дуги** + `SUSPICIOUS (no reflection): …` — направления без
  возврата вообще;
* белый крест — точка исчезания C;
* консольный лог раз в 15 кадров (и при каждом отчёте): стена, ближний,
  число ячеек, длина полосы, подозрительные интервалы, CPU мс, fps.

## Параметры командной строки

| параметр | смысл |
|---|---|
| `--cam N` | индекс камеры (по умолчанию 0) |
| `--video FILE` | обрабатывать видеофайл вместо камеры |
| `--cal FILE` | файл калибровки (по умолчанию `calibration.json`) |
| `--rcal FILE` | файл точки исчезания (по умолчанию `radar_calibration.json`; строится из `--cal`, если нет) |
| `--cal-dir DIR` | каталог калибровочных изображений (по умолчанию `./calibration`) |
| `--build-calib` | вычислить точку исчезания из `--cal`, сохранить в `--rcal` и выйти |
| `--test` | прогнать валидацию по 28 изображениям и выйти |
| `--ascii` | вместе с `--test`: дополнительно печатать ASCII-радары |
| `--min-brightness F` | вместо top-hat маски — обычный порог яркости (пересвеченные сцены) |
| `--min-row N` | минимум светящихся ячеек в строке, чтобы считать её поверхностью (по умолчанию 3) |
| `--sub-cal` | разрешать ближних кандидатов ниже ближайшей калибровочной дистанции (экспериментально) |
| `--dmax M` | отбрасывать ближних кандидатов дальше M (по умолчанию 13.2 м = дальняя граница калибровки) |
| `--no-persist` | отчитывать ближние объекты без 3-кадрового подтверждения |
| `--no-live-mask` | не обучать живую junk-маску сцены |
| `--boot-frames N` | сколько кадров использовать для обучения живой маски (по умолчанию 120) |
| `--live-fraction F` | ячейка, светящаяся в ≥ F стартовых кадров, считается статичной (по умолчанию 0.25) |
| `--debug-polar` | дополнительное большое окно радар-экрана |
| `--no-gui` | без окна (batch / headless) |
| `--max-frames N` | остановиться после N кадров (0 = работать до q) |
| `--csv FILE` | CSV по кадрам: `frame,wall_m,near_m,near_theta,fam,reported,susp,cpu_ms` |
| `--out FILE` | *отключено в этой сборке* (запись закоментирована; параметр оставлен для совместимости) |

## Калибровка

`calibration.json` (версия 1) содержит:

* **model** — пинhole-камера (высота ≈ 0.286 м над опорной плоскостью,
  yaw/pitch/roll ≈ 0, fx = fy ≈ 3000, главная точка (640, 360)) плюс три
  плоскости вееров (единичная нормаль + сдвиг c на каждую). Мировая
  система: X вправо, Y вверх, Z вперёд.
* **maps** — по одному `LineMap` на веер: 28 узлов (d, x0(d), m(d)) в
  диапазоне **1.955 … 13.2 м**; L/R — вертикальные линии
  `x = m(y−360) + x0`, B — горизонтальная `y = m(x−640) + x0`, всё в
  опорном кадре 1280×720.
* **report** — наихудший пиксельный остаток подгонки по каждому кадру
  (худший ≈ 15 px в кадре 1.955 м, медиана ≈ 11 px).
* **meta** — число образцов и диапазон дистанций.

Карты подогнаны (Levenberg–Marquardt, реализация в `laser_sensor.py`) по
28 изображениям тёмного помещения: калибровочная доска двигалась вдоль
оси Z, эталонная дистанция каждого кадра — в
`calibration/camera_calibration.xlsx`.

**Повторная калибровка** (нужна, если поменялась камера или геометрия
лазеров): подгонщик `calibrate.py` в этот минимальный пакет *не* входит —
он лежит в dev-дереве проекта. Если прогоните его заново, передайте новый
файл через `--cal`, выполните `--build-calib` и удалите `radar_junk.npy`,
чтобы статическая маска пересобралась под новую геометрию.

## Валидация

`python3 laser_radar_final.py --test` (в этих кадрах калибровочная доска
*и есть* ближайшая поверхность: она должна отчитываться как стена и не
должна давать ни одного ближнего объекта):

```
wall (=board face):  RMS = 0.222 m,  max = 0.454 m  over 27 images
spurious near objects on flat-board images: 0
```

(только кадры в пределах диапазона; кадр 1.955 м ниже 2-метрового пола
радара по построению и отчитывается как `OUT(<2m)`).

## Настройка

Все «крутилки» — в блоке `# ---- tuning ----` в начале
`laser_radar_final.py`:

| константа | значение | роль |
|---|---|---|
| `THETA_STEP` | 0.3° | угловое разрешение матрицы |
| `D_MIN` / `D_MAX` | 2.0 / 40 м | диапазон строк радара |
| `NEAR_STEP` / `FAR_STEP` | 0.02 / 1.0 м | разрешение строк внутри / за калибровочным диапазоном |
| `MIN_ROW_ACT` | 3 | минимум светящихся ячеек в строке, чтобы считать её поверхностью |
| `WALL_ACT_MIN` | 200 | пиковая оценка, чтобы строка считалась «стеной» |
| `STREAK_MIN` | 8 | сколько соседних угловых столбцов образуют настоящую полосу |
| `SPOT_MIN_AREA` / `SPOT_MIN_EXT` | 10 / 5 px | площадь пятна / протяжённость вдоль линии — правило «это объект» |
| `SPOT_N_MEASURE` | 20 px | только эти ближайшие пиксели определяют отчитываемую дистанцию (ближняя грань) |
| `SPOT_MAX_OFF` | 5 px | максимальное медианное смещение пикселей от линии — «лежит на линии» |
| `SPOT_WALL_MARGIN` | 0.25 m | ближний объект должен быть на столько впереди стены |
| `PERSIST` | 3 | сколько кадров кандидат должен держаться до отчёта |

## Замечания и ограничения

* Пол 2 м и потолок `--dmax` 13.2 м заданы намеренно: вне
  откалиброванного диапазона 1.955–13.2 м карты линий экстраполируются
  (ветвь 1/d) — этого достаточно, чтобы *локализовать*, но недостаточно,
  чтобы *отчитывать* вслепую.
* Малый объект может пересекать **один** лазерный веер, даже на 13 м, —
  подтверждение вторым веером намеренно *не* требуется; от призраков
  защищают junk-маски, проверка засветки и 3-кадровая персистенция.
* Камера отдаёт столько кадров, сколько позволяет её железо (обычно
  10–15 fps при 1280×720 по USB MJPG); обработка стоит несколько мс,
  поэтому итоговая частота ограничена камерой. При старте приложение
  замеряет фактическую частоту и печатает её.
* Тряска камеры от руки прощается за счёт 3×3-дилатации в 3-кадровом
  накоплении; из живой junk-маски исключена полоса стены, чтобы само
  измерение никогда не маскировалось.
* Машина без дисплея: запускайте с `--no-gui` (и `--csv` для данных);
  OpenCV GUI нужна только для живого окна.
